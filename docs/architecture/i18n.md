# Internationalization Strategy

This document defines day-0 internationalization requirements for Sail Tracker.

## Core Rule

Multi-language support is a foundational concern. The application must be designed so language handling is part of normal development from the first screen.

## Initial Assumptions

- The app will support multiple languages.
- The first likely languages are English and Danish.
- The exact launch language set can be confirmed later.

## Language Scope

Internationalization applies to:

- UI labels and content
- validation messages
- empty states and errors
- emails and invitations later
- demo and seeded content where user-facing
- date, time, and number formatting

## Locale Levels

The design should allow these settings:

- platform default locale
- tenant default locale
- user preferred locale

User preference should eventually override tenant default where appropriate.

## Day-0 Rules

- Do not hardcode user-facing strings as the long-term pattern.
- Do not build copy by concatenating translated fragments.
- Keep translation keys stable and domain-oriented.
- Keep locale-aware formatting separate from core domain logic.

## UX Considerations

- Mobile-first layouts must survive longer translated strings.
- Empty states and errors must remain understandable in every supported language.
- Dates and times must respect user expectations for locale formatting.

## Seed And Demo Content

- The demo tenant should use translatable content patterns.
- Seed data should not assume English-only labels forever.
- Domain reference data that will be visible to users should have a localization strategy.

## Development Guidance

- Choose one translation mechanism early and use it consistently.
- Keep language resources structured by domain or feature area.
- Review new screens for text expansion risk.
- Add translation coverage to code review expectations.

## Open Questions

- Exact launch languages.
- Whether club-specific terminology needs tenant-level customization.
- Whether system-generated exports and PDFs must be localized in the first release.
