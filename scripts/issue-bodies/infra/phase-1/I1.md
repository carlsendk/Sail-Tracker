### Goal

Add `pnpm` scripts that wrap the four core Supabase CLI commands so every developer can manage the local database through the same interface as the rest of the toolchain.

### Context

Supabase CLI is already installed as a devDependency (`supabase@^2.78.1`) but there are no `package.json` scripts exposing its common operations. Every subsequent Phase 1 issue (`#22`, `#23`, `#24`) and any future CI step builds on these script names being stable. Establishing them first makes the whole local path composable.

### Embedded Spec

From `docs/plans/plan.md` § Phase 1 → Scope:

> - add documented scripts for `supabase start`, `supabase stop`, `supabase status`, and `supabase db reset`

From `docs/plans/plan.md` § Phase 1 → Success condition:

> a new developer can start local Supabase, reset the database, bootstrap baseline data, and run the web app without pointing at a hosted project

### Files

- Modify: `package.json` (root) — add four new scripts under `"scripts"`
- No new files needed; the Supabase CLI binary is already on PATH via `node_modules/.bin/supabase`

Script names to add:

```json
"supabase:start":  "supabase start",
"supabase:stop":   "supabase stop",
"supabase:status": "supabase status",
"supabase:reset":  "supabase db reset"
```

Note: `supabase:reset` does NOT chain `pnpm bootstrap:supabase` here — the bootstrap step requires env vars that may not be set in every context. The chained "full local reset" loop (`supabase:reset` → `bootstrap:supabase`) is documented in `#24` as the recommended dev workflow, not baked into this script.

### Acceptance Criteria

- [ ] `pnpm supabase:start` runs `supabase start` (starts local Supabase containers)
- [ ] `pnpm supabase:stop` runs `supabase stop`
- [ ] `pnpm supabase:status` runs `supabase status` and exits 0 when Supabase is running, non-zero when stopped
- [ ] `pnpm supabase:reset` runs `supabase db reset` (applies migrations and seed.sql on the local DB)
- [ ] All four scripts are in root `package.json` under `"scripts"`, so they are visible in `pnpm run --help` output
- [ ] `pnpm validate` still passes after the change (scripts section only; no runtime code changed)

### TDD Steps

1. Read `package.json` and confirm none of the four script keys exist yet (they shouldn't).
2. Add the four script entries to the `"scripts"` block in `package.json`.
3. Run `pnpm supabase:status` — if Docker is not running, expect a non-zero exit and a helpful CLI error. If Docker is running with no containers, expect an informative "not running" message. This is the expected state before `start`.
4. Run `pnpm supabase:start` (requires Docker). Expect the CLI to print container startup output and exit 0.
5. Run `pnpm supabase:status`. Expect exit 0 and a table of running services with their local URLs and ports.
6. Run `pnpm supabase:stop`. Expect containers to stop and exit 0.
7. Run `pnpm validate` to confirm no regression.
8. Commit `chore(infra): add supabase cli pnpm scripts`.
