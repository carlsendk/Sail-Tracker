### Goal

Make `scripts/bootstrap-supabase.mjs` accept local Supabase CLI credentials so that `pnpm supabase:reset && pnpm bootstrap:supabase` populates baseline data on a local database without requiring a hosted Supabase project.

### Context

The bootstrap script currently rejects any key that does not start with `sb_secret_` (line 69-74 of `scripts/bootstrap-supabase.mjs`). The Supabase CLI emits a JWT-format `service_role` key — not `sb_secret_*` — so the guard always rejects local runs. Additionally, the local API URL is `http://127.0.0.1:54321`, not a hosted project URL. Both values must come from `.env.local` for local development. This is the integration issue that closes the Phase 1 success condition.

### Embedded Spec

From `docs/plans/plan.md` § Phase 1 → Scope:

> - make the bootstrap flow work against local Supabase as well as hosted Supabase

From `docs/plans/plan.md` § Phase 1 → Success condition:

> a new developer can start local Supabase, reset the database, bootstrap baseline data, and run the web app without pointing at a hosted project

### Files

- Modify: `scripts/bootstrap-supabase.mjs`
  - Relax or reroute the `isPrivilegedSupabaseKey` check so that local JWT-format `service_role` keys are accepted when running against a local Supabase URL (e.g. `http://127.0.0.1:54321` or `http://localhost:54321`)
  - Keep the guard for hosted projects: the `sb_secret_*` check should still apply when `NEXT_PUBLIC_SUPABASE_URL` points at a non-local host
  - Detection pattern: if `NEXT_PUBLIC_SUPABASE_URL` hostname is `127.0.0.1` or `localhost`, treat any non-empty `SUPABASE_SERVICE_ROLE_KEY` value as valid

- Modify: `.env.example`
  - Add a commented "Local Supabase" block with the two variables a developer must set for local use:
    ```
    # Local Supabase (from `pnpm supabase:status` or `supabase status`)
    # NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
    # SUPABASE_SERVICE_ROLE_KEY=<service_role JWT from supabase status>
    ```

- Modify: `docs/development/local-supabase.md`
  - Add a final "Running the full local loop" section:
    1. `pnpm supabase:start`
    2. `pnpm supabase:reset` (applies migrations + seed.sql)
    3. Copy `service_role` key from `pnpm supabase:status` output into `.env.local` along with `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321` and `PLATFORM_ADMIN_EMAIL=<your-email>`
    4. `pnpm bootstrap:supabase`
    5. `pnpm dev`

3. In `scripts/bootstrap-supabase.mjs`, replace the unconditional `isPrivilegedSupabaseKey` check with a local-aware variant:
   ```js
   function isLocalSupabaseUrl(url) {
     try {
       const host = new URL(url).hostname;
       return host === "127.0.0.1" || host === "localhost";
     } catch {
       return false;
     }
   }
   // Then in guard:
   if (!isLocalSupabaseUrl(supabaseUrl) && !isPrivilegedSupabaseKey(secretKey)) {
     console.error("SUPABASE_SERVICE_ROLE_KEY must be a Supabase secret key in the form sb_secret_...");
     process.exit(1);
   }
   ```
4. Re-run the test — expect the guard assertions to pass.
5. Against a running `pnpm supabase:start` + `pnpm supabase:reset`, set `.env.local` and run `pnpm bootstrap:supabase`. Expect "Supabase bootstrap complete" and a JSON summary.
6. Update `.env.example` and `docs/development/local-supabase.md` as described in Files.
