### Goal

Add a Supabase CLI installation step to `.github/workflows/ci.yml` so subsequent CI steps can invoke `supabase` commands reliably and with a pinned version.

### Context

This is the first task in Phase 3 (Database Validation In CI). The remaining Phase 3 issues (#30, #31, #32) all assume `supabase` is on the runner PATH. Without this step the CLI is absent on `ubuntu-latest` and every downstream `supabase start` or `supabase db` invocation fails with "command not found". The `supabase/setup-cli@v1` action handles installation, version pinning, and binary caching.

### Embedded Spec

From `docs/plans/plan.md` § Phase 3 → Scope:

> - install and run Supabase CLI in GitHub Actions

Success condition from the same section:

> CI fails if migrations, seed data, bootstrap, or database-dependent app behavior are broken

### Files

- Modify: `.github/workflows/ci.yml` — add one new step

### Acceptance Criteria

- [ ] `.github/workflows/ci.yml` contains `uses: supabase/setup-cli@v1` in the `validate` job
- [ ] The step is positioned after `Enable corepack` and before `Install dependencies` so the CLI is available for any future pre-install hook that might reference it
- [ ] A `version` input is pinned (e.g. `version: 2`) rather than defaulting to `latest`, making upgrades intentional
- [ ] CI run logs show `supabase --version` output confirming the binary is available (add a one-line diagnostic step `run: supabase --version` immediately after the setup step)
- [ ] No other CI steps are modified or reordered

### TDD Steps

The workflow file itself is the deliverable; there is no unit test to write. The TDD cycle is:

1. On a feature branch, add `uses: supabase/setup-cli@v1` to `.github/workflows/ci.yml` **without** a `version` input to confirm the step structure is otherwise valid.
2. Push the branch. The Actions run should proceed past setup and fail only on a downstream step that does not yet exist (e.g. `supabase start` missing in subsequent issues). This proves the step does not crash on its own.
3. Pin `version: 2` and add the diagnostic `run: supabase --version` step. Push again. Observe the logs — the version string must appear before the `Install dependencies` step runs.
4. Confirm the existing `Lint`, `Typecheck`, `Test`, and `Build` steps all still pass unchanged.
