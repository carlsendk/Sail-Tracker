### Goal

Add a `validate` job to `deploy-prod.yml` that re-runs the full CI suite before any production action, refusing to proceed if any check fails. Refactor `ci.yml` into a reusable callable workflow so the validation step is not duplicated.

### Context

The existing `.github/workflows/ci.yml` runs lint, typecheck, tests, and database checks on PR and push to main. Before this issue the production deploy workflow (skeleton from #33) has no jobs. This issue adds the first real job: `validate`. The job must mirror everything CI checks — if it passes in CI it must pass here, and if it fails the deploy is blocked entirely. Reusing CI as a callable workflow rather than duplicating the steps is the preferred approach; it ensures the gate and the CI check are definitionally the same.

### Embedded Spec

From `docs/plans/plan.md` § Phase 4 → Scope:

> - run validation before deploy

### Files

- Modify: `.github/workflows/ci.yml` — expose as a reusable workflow via `on: workflow_call` (in addition to existing `on: pull_request` / `on: push` triggers) so `deploy-prod.yml` can call it without duplicating steps.
- Modify: `.github/workflows/deploy-prod.yml` — add `validate` job that calls the reusable CI workflow; all subsequent jobs must declare `needs: validate`.

`validate` job shape in `deploy-prod.yml`:

```yaml
jobs:
  validate:
    uses: ./.github/workflows/ci.yml
    secrets: inherit
```

If refactoring `ci.yml` to `workflow_call` proves too invasive (e.g., matrix differences), an acceptable fallback is an inline `validate` job that duplicates the key steps and adds a comment explaining the duplication. Document the trade-off in the PR description.

### Acceptance Criteria

- [ ] `deploy-prod.yml` contains a `validate` job that runs before any deployment action
- [ ] Validation covers at minimum: lint, typecheck, unit/integration tests, and database migration tests (matching current `ci.yml` coverage)
- [ ] If any validation step fails, the workflow exits without touching production Supabase or Vercel
- [ ] No CI check is duplicated in code without a comment explaining why (prefer `workflow_call`)
- [ ] `pnpm validate` still passes locally after the change

### TDD Steps

1. Confirm `ci.yml` does not yet have `on: workflow_call` in its trigger block.
2. Add `workflow_call` to `ci.yml`'s `on:` block. Push a test branch.
3. In the test branch, add the `validate` job to `deploy-prod.yml` (calling `ci.yml`). Push.
4. Observe GitHub Actions: expect the `validate` job to appear and run the full CI suite. On a clean branch it should pass.
5. Introduce a deliberate lint error in the test branch (e.g., an unused import) and push again. Expect `validate` to fail and no subsequent jobs to start.
6. Revert the deliberate error; confirm `validate` passes again.
7. Remove the test branch. Ensure `main`'s `ci.yml` is updated before merging #34.
8. Commit `chore(infra): add validate gate to deploy-prod workflow`.
