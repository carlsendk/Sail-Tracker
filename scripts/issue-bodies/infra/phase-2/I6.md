### Goal

Document the canonical local environment contract — the key names emitted by the Supabase CLI — and provide a `.env.local.example` template so a developer can get from `supabase status` output to a running app in one copy-paste step.

### Context

Local Supabase (started via `pnpm supabase:start` from #21) emits JWT-format keys at startup: an `anon key` and a `service_role key`. These are standard JWTs, not the `sb_publishable_*` / `sb_secret_*` format used by hosted projects. The bootstrap script currently guards against non-`sb_secret_...` keys (`bootstrap-supabase.mjs:65-73`), so a developer who pastes local CLI keys will hit a validation error with no obvious explanation. This issue closes the documentation gap and provides the `.env.local.example` template that maps local CLI output to the env vars the app reads — the mode-aware resolver in #27 will handle the code path.

The local contract is intentionally separate from the hosted contract documented in #25: the two modes use different key formats and different URL shapes (`http://127.0.0.1:54321` vs `https://<project-ref>.supabase.co`).

### Embedded Spec

From `docs/plans/plan.md` § Phase 2:

> ## Phase 2: Environment Contract Cleanup
>
> Make environment handling explicit for both hosted and local modes.
>
> Scope:
>
> - define the hosted env contract using `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` and `SUPABASE_SECRET_KEY`
> - define the local env contract using CLI-provided local credentials where required
> - add a small resolver layer so the app and bootstrap logic can choose the correct key set by environment
> - remove unnecessary legacy fallbacks once the supported local path is clear
>
> Success condition:
>
> - there is one documented env contract for hosted development and one for local development, with no ambiguity about which keys are expected

### Files

- Extend: `docs/development/env-contract.md` — add a "Local (CLI) mode" section after the hosted section
- Create: `.env.local.example` — template for local development, pre-filled with the default local CLI values

`docs/development/env-contract.md` — local mode section should cover:

1. How to retrieve local values: run `pnpm supabase:status` and read the output table. The CLI prints `API URL`, `anon key`, and `service_role key`.

2. Variable mapping table:

   | Variable | Maps to CLI output | Notes |
   |---|---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | `API URL` | Default: `http://127.0.0.1:54321` |
   | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | `anon key` | JWT format; not `sb_publishable_...` |
   | `SUPABASE_SECRET_KEY` | `service_role key` | JWT format; not `sb_secret_...` |

3. Explanation that local keys are JWTs (long Base64 strings), not the `sb_*` prefixed keys used by hosted projects — both formats are valid secrets; the format difference is intentional.

4. Instructions to copy `.env.local.example` to `.env.local` and replace any `<placeholder>` values with output from `pnpm supabase:status`.

`.env.local.example` pre-fills default local ports so copy-paste works for most setups:

```
# Local Supabase — values from `pnpm supabase:status`
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<anon key from supabase status>
SUPABASE_SECRET_KEY=<service_role key from supabase status>
PLATFORM_ADMIN_EMAIL=admin@localhost
```

### TDD Steps

This is primarily a docs issue. Use the "follow the doc on a clean checkout" pattern:

1. Run `pnpm supabase:start` (from #21) and `pnpm supabase:status`. Observe the output structure — confirm the field names (`API URL`, `anon key`, `service_role key`).
2. Add the "Local (CLI) mode" section to `docs/development/env-contract.md`. Include the mapping table and the JWT format note.
3. Create `.env.local.example` at the repository root with the four entries above.
4. Verify `.gitignore` does not exclude `*.example` files (example files with placeholder values are safe to commit).
5. Copy `.env.local.example` to `.env.local`, paste in the actual keys from `pnpm supabase:status`.
6. Start the web app (`pnpm dev`) and confirm it connects to local Supabase without errors in the console.
7. Run `pnpm validate`. Expect PASS.
8. Commit `docs(infra): document local env contract`.
