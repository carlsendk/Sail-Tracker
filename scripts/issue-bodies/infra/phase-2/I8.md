### Goal

Remove every legacy env fallback now that the resolver (#27) is the single source of truth, and update tests to assert that misconfiguration is a hard error rather than a silent degradation.

### Context

Two fallback chains currently mask configuration errors:

1. `apps/web/lib/supabase-admin.ts:19` — `resolveSupabaseAdminConfig` reads `SUPABASE_SERVICE_ROLE_KEY ?? SUPABASE_SECRET_KEY`. After #27, this function should delegate entirely to `resolveSupabaseEnv()` from `apps/web/lib/env.ts`. Any remaining direct key reads are dead code.

2. `scripts/bootstrap-supabase.mjs:47` — same dual-read `SUPABASE_SERVICE_ROLE_KEY ?? SUPABASE_SECRET_KEY`. After #27, the bootstrap script no longer reads keys directly; it uses the mode-aware resolver (inline or imported). This fallback is therefore also dead code.

Additionally, `supabase-admin.ts` currently returns `null` when config is incomplete (line 21-24) — callers silently do nothing. With the resolver throwing on misconfig, this soft-failure path is no longer appropriate: a missing config should be a loud error at startup, not a quiet no-op at request time.

The existing test in `apps/web/tests/supabase-admin.test.ts` explicitly tests "falls back to the legacy secret key when needed" — that test must be deleted (the behaviour it tests is being removed) and replaced with a test asserting a throw on misconfig.

### Embedded Spec

From `docs/plans/plan.md` § Phase 2:

> ## Phase 2: Environment Contract Cleanup
>
> Make environment handling explicit for both hosted and local modes.
>
> Scope:
>
> - define the hosted env contract using `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` and `SUPABASE_SECRET_KEY`
> - define the local env contract using CLI-provided local credentials where required
> - add a small resolver layer so the app and bootstrap logic can choose the correct key set by environment
> - remove unnecessary legacy fallbacks once the supported local path is clear
>
> Success condition:
>
> - there is one documented env contract for hosted development and one for local development, with no ambiguity about which keys are expected
