### Goal

Implement a single TypeScript env resolver module that reads the correct Supabase key set based on the active mode (hosted vs local), throws a clear error when configuration is missing or malformed, and is consumed by both the web app and the bootstrap script.

### Context

Today, env reading is scattered across three places:

- `apps/web/lib/supabase-admin.ts:19` — reads `SUPABASE_SERVICE_ROLE_KEY ?? SUPABASE_SECRET_KEY` (fallback chain, silently accepts either name)
- `scripts/bootstrap-supabase.mjs:47` — same dual-read in raw ESM
- `scripts/bootstrap-supabase.mjs:65-73` — `isPrivilegedSupabaseKey` gate that asserts `sb_secret_...` prefix, which rejects valid local JWT keys

The resolver consolidates all of this. It knows whether the environment is hosted or local and applies the correct validation rules for each: hosted keys must carry the `sb_publishable_*` / `sb_secret_*` prefix; local keys are JWTs and must not be tested against those prefixes.

**Cross-runtime constraint.** The web app is TypeScript/ESM; the bootstrap script is a raw `.mjs` file with no build step. A module in `apps/web/lib/` cannot be directly `import`-ed by the script. Two approaches are viable — the implementer should choose one and call it out in the PR:

- **Option A (recommended for now):** Place the resolver in `apps/web/lib/env.ts` and have the bootstrap script duplicate only the thin mode-detection + key-reading logic (five lines) calling shared env-file loading logic that already exists in `bootstrap-supabase.mjs`. The script then does its own resolver inline, matching the documented contract.
- **Option B:** Move the resolver to `packages/infrastructure/src/env.ts` (a proper shared package) and give the bootstrap script a build step (`tsx` or `ts-node`) so it can import it. This is the correct long-term home but adds complexity; Phase 2 may not be the right time.

The body proposes Option A. If the implementer picks Option B, they must also update `scripts/bootstrap-supabase.mjs` to use `tsx` or add a compiled output step.

**Mode detection.** The resolver uses a `SUPABASE_MODE` env var: `"hosted"` or `"local"`. If unset, it auto-detects based on `NEXT_PUBLIC_SUPABASE_URL`: URLs matching `http://127.0.0.1` or `http://localhost` → local; everything else → hosted. This keeps `.env.local` minimal (no extra variable needed) while allowing an explicit override.

**Integration with `server-env.ts`.** The web app already has `apps/web/lib/server-env.ts` which handles `.env.local` / `.env` file precedence and `process.env` fallthrough via `getServerEnv`. The resolver should consume `getServerEnv` rather than re-implement file loading.

**Proposed API for `apps/web/lib/env.ts`:**

```typescript
export type SupabaseMode = "hosted" | "local";

export type SupabaseEnv = {
  mode: SupabaseMode;
  url: string;
  publishableKey: string;
  secretKey: string;
};

/**
 * Resolves the Supabase environment for the current mode.
 * Throws if any required variable is missing or if the key format is wrong
 * for the detected mode.
 *
 * @param readEnv - injectable for tests; defaults to getServerEnv
 */
export function resolveSupabaseEnv(
  readEnv?: (name: string) => string | null,
): SupabaseEnv;
```

Throwing behavior:
- Missing `NEXT_PUBLIC_SUPABASE_URL` → `Error: NEXT_PUBLIC_SUPABASE_URL is required`
- Missing publishable key → `Error: NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY is required`
- Missing secret key → `Error: SUPABASE_SECRET_KEY is required`
- Hosted mode with non-`sb_secret_...` secret key → `Error: SUPABASE_SECRET_KEY must start with sb_secret_ in hosted mode`
- Hosted mode with non-`sb_publishable_...` publishable key → `Error: NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY must start with sb_publishable_ in hosted mode`
- Local mode → no prefix check applied (JWT format accepted)

### TDD Steps

Write `apps/web/tests/env.test.ts` before implementing `env.ts`:

```typescript
import { describe, expect, it } from "vitest";
import { resolveSupabaseEnv } from "../lib/env";

// Helper to build a mock readEnv from a partial env shape
function makeEnv(values: Record<string, string>) {
  return (name: string) => values[name] ?? null;
}
```

1. **Missing URL throws.**

   ```typescript
   it("throws when NEXT_PUBLIC_SUPABASE_URL is missing", () => {
     expect(() => resolveSupabaseEnv(makeEnv({}))).toThrow("NEXT_PUBLIC_SUPABASE_URL");
   });
   ```

2. **Hosted mode: valid shape returns resolved values.**

   ```typescript
   it("resolves hosted env when all hosted keys are present", () => {
     const env = resolveSupabaseEnv(makeEnv({
       NEXT_PUBLIC_SUPABASE_URL: "https://example.supabase.co",
       NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: "sb_publishable_abc123",
       SUPABASE_SECRET_KEY: "sb_secret_xyz789",
     }));
     expect(env.mode).toBe("hosted");
     expect(env.secretKey).toBe("sb_secret_xyz789");
   });
   ```

3. **Hosted mode: wrong secret-key prefix throws.**

   ```typescript
   it("throws in hosted mode when secret key is not sb_secret_ prefixed", () => {
     expect(() => resolveSupabaseEnv(makeEnv({
       NEXT_PUBLIC_SUPABASE_URL: "https://example.supabase.co",
       NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: "sb_publishable_abc123",
       SUPABASE_SECRET_KEY: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
     }))).toThrow("sb_secret_");
   });
   ```

4. **Local mode: JWT keys accepted without prefix check.**

   ```typescript
   it("resolves local env when JWT keys are supplied with local URL", () => {
     const jwtKey = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJyb2xlIjoic2VydmljZV9yb2xlIn0.fake";
     const env = resolveSupabaseEnv(makeEnv({
       NEXT_PUBLIC_SUPABASE_URL: "http://127.0.0.1:54321",
       NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: jwtKey,
       SUPABASE_SECRET_KEY: jwtKey,
     }));
     expect(env.mode).toBe("local");
     expect(env.secretKey).toBe(jwtKey);
   });
   ```

5. **Explicit `SUPABASE_MODE=local` overrides URL-based detection.**

   ```typescript
   it("respects SUPABASE_MODE=local even for a non-local URL", () => {
     const jwtKey = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJyb2xlIjoic2VydmljZV9yb2xlIn0.fake";
     const env = resolveSupabaseEnv(makeEnv({
       SUPABASE_MODE: "local",
       NEXT_PUBLIC_SUPABASE_URL: "https://example.supabase.co",
       NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: jwtKey,
       SUPABASE_SECRET_KEY: jwtKey,
     }));
     expect(env.mode).toBe("local");
   });
   ```

6. **Missing secret key throws.**

   ```typescript
   it("throws when SUPABASE_SECRET_KEY is missing", () => {
     expect(() => resolveSupabaseEnv(makeEnv({
       NEXT_PUBLIC_SUPABASE_URL: "https://example.supabase.co",
       NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY: "sb_publishable_abc123",
     }))).toThrow("SUPABASE_SECRET_KEY");
   });
   ```
