### Goal

Configure Vitest coverage with conservative initial thresholds so future regressions in test coverage fail CI.

### Context

This is the fourteenth and final Phase 0 task. It depends on B11 (Vitest must already have RTL/jsdom wired). Initial thresholds are deliberately conservative; later tier issues raise them as product code lands with proper tests.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> Vitest + React Testing Library + Playwright wired up; coverage thresholds set

Per the Phase 0 issue table (row B14): file `vitest.config.ts` (the apps/web one). Acceptance: `pnpm test --coverage` produces report; threshold breach fails CI. Coverage: initial thresholds conservative (e.g. 50% lines), tightened later.

### Files

- Modify: `apps/web/vitest.config.ts` — add `coverage` block with `provider: "v8"`, `reporter: ["text", "html", "lcov"]`, `thresholds: { lines: 50, functions: 50, branches: 40, statements: 50 }`, sensible `include`/`exclude`
- Modify: `apps/web/package.json` — add `test:coverage` script; add dev dep `@vitest/coverage-v8`
- Modify: `package.json` (root) — add a `coverage` pass-through script
- Modify: `.gitignore` — ignore `coverage/`, `apps/web/coverage/`
- Test: `pnpm --filter web test:coverage`

### Acceptance Criteria

- [ ] `apps/web/vitest.config.ts` has a `coverage` block with thresholds (lines/functions/branches/statements)
- [ ] `pnpm --filter web test:coverage` produces a text report and fails if any threshold is unmet
- [ ] `coverage/` is in `.gitignore`
- [ ] B13's CI workflow `test` job runs with `--coverage` (modify the workflow if B13 already merged; otherwise note in PR body that B13 will pick it up)
- [ ] Thresholds chosen are documented in a brief comment in the config (one-liner stating "raise as tests land")

### TDD Steps

1. Install `@vitest/coverage-v8` in `apps/web`.
2. Edit `apps/web/vitest.config.ts` with the coverage block + thresholds.
3. Run `pnpm --filter web test:coverage`; verify report printed and pass/fail behavior.
4. Adjust thresholds downward if real coverage is below 50% lines initially (record actual numbers in PR body); the goal is to set a floor, not block this PR.
5. Update `.gitignore` to exclude coverage outputs.
6. Commit `test(web): add coverage thresholds`; PR `Closes #<this-issue>`.
