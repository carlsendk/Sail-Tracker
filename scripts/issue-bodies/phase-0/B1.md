### Goal

Tighten `tsconfig.base.json` with the strictest practical TypeScript options so type errors are caught uniformly across the workspace.

### Context

This is the first task in Phase 0 (Code Quality Foundation). Strict typing is a precondition for the type-aware ESLint rules in B2 and the layer-enforcement rules in B3. Today `tsconfig.base.json` only sets `strict: true`; this issue layers on the additional flags listed in the canonical plan and fixes any code that the new flags surface.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> TypeScript strict mode at the most aggressive level the codebase tolerates (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`)

Per the Phase 0 issue table in `docs/plans/2026-05-07-agent-backlog-bootstrap.md` (row B1), this issue also enables `noFallthroughCasesInSwitch` and `forceConsistentCasingInFileNames`.

Acceptance derived from the same table row: `pnpm typecheck` clean across workspace.

### Files

- Modify: `tsconfig.base.json`
- Modify (only if drift surfaces): each `tsconfig.json` in `apps/*` and `packages/*` to ensure `extends: "../../tsconfig.base.json"` (or equivalent) is present
- Test: run `pnpm -r typecheck` (or `pnpm typecheck` from each workspace if recursive script is missing)

### Acceptance Criteria

- [ ] `tsconfig.base.json` enables `noUncheckedIndexedAccess`
- [ ] `tsconfig.base.json` enables `exactOptionalPropertyTypes`
- [ ] `tsconfig.base.json` enables `noImplicitOverride`
- [ ] `tsconfig.base.json` enables `noPropertyAccessFromIndexSignature`
- [ ] `tsconfig.base.json` enables `noFallthroughCasesInSwitch`
- [ ] `tsconfig.base.json` enables `forceConsistentCasingInFileNames`
- [ ] `pnpm typecheck` runs clean in every workspace package that has a typecheck script
- [ ] No code is loosened (e.g. `as any`, `// @ts-ignore`, narrowing types via `!`) to make typecheck pass; real fixes only

### TDD Steps

1. Add the six new compiler options to `tsconfig.base.json`.
2. Run `pnpm typecheck` (or per-workspace equivalents). Expect FAIL listing real offenders.
3. Fix offenders one at a time; prefer narrowing (`if`/`?.`/explicit guards) over assertions.
4. Re-run typecheck → expect PASS.
5. Commit `chore(ts): tighten strict mode in tsconfig.base.json`; open PR with `Closes #<this-issue>`.
