### Goal

Require `data-testid` on every interactive element (`button`, `a`, `[role="button"]`) outside test files, so end-to-end tests have stable selectors.

### Context

This is the fifth Phase 0 task and depends on B2. Without enforced testids, e2e tests rely on text content or DOM positions — both fragile. This rule guarantees that every interactive element our users click on is uniquely addressable by tests.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> Custom rules: no inline SVG (use `packages/ui/src/icons/`), `data-testid` required on interactive elements outside test files

Per the Phase 0 issue table (row B5): `button`, `a`, `[role="button"]` must require `data-testid` outside test files; a button without `data-testid` should fail lint.

### Files

- Modify: `eslint.config.mjs` (root) — add a custom rule (via `no-restricted-syntax` AST selectors or a small in-repo rule plugin) requiring `data-testid` on the listed interactive elements; exempt files matching `**/*.{test,spec}.{ts,tsx}` and `apps/web/__tests__/**`
- Create: `tests/eslint-data-testid.test.mjs` — programmatic lint test (negative + positive)
- Test: `pnpm lint`, the new test

### Acceptance Criteria

- [ ] A `<button>` JSX element without `data-testid` outside test files reports the rule
- [ ] A `<button data-testid="…">` element does not report the rule
- [ ] An `<a>` JSX element without `data-testid` outside test files reports the rule
- [ ] A JSX element with `role="button"` without `data-testid` reports the rule
- [ ] The rule does NOT fire inside files matching `**/*.{test,spec}.{ts,tsx}` or `apps/web/__tests__/**`
- [ ] Existing components that fail this rule are either fixed in this PR or recorded as follow-ups (operator decides per-case)

### TDD Steps

1. Author `tests/eslint-data-testid.test.mjs` covering: missing-testid button (FAIL), present-testid button (PASS), `role="button"` without testid (FAIL), test-file exception (PASS). Run → FAIL.
2. Add the rule to `eslint.config.mjs`. Prefer a `no-restricted-syntax` set with AST selectors over a custom-plugin if possible; if it must be a plugin, place the rule under `tools/eslint-rules/`.
3. Re-run tests → PASS.
4. Run `pnpm lint`; address any existing violations (most should be in `apps/web` page components).
5. Commit `chore(eslint): require data-testid on interactive elements`; PR `Closes #<this-issue>`.
