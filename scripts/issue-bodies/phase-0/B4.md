### Goal

Forbid inline `<svg>` JSX in component code; require icons to live under `packages/ui/src/icons/` and be imported as components.

### Context

This is the fourth Phase 0 task and depends on B2. Inline SVGs in components inflate diffs, complicate accessibility audits, and prevent shared-icon reuse. This issue establishes the no-inline-SVG rule and the icon-package convention.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> Custom rules: no inline SVG (use `packages/ui/src/icons/`), `data-testid` required on interactive elements outside test files

Per the Phase 0 issue table (row B4): a negative lint test (`<svg>` JSX in component code) must fail; `<svg>` is only allowed inside `packages/ui/src/icons/`.

### Files

- Modify: `eslint.config.mjs` (root) — add a `no-restricted-syntax` rule (or equivalent) that forbids `JSXElement[openingElement.name.name="svg"]` outside `packages/ui/src/icons/**`
- Create: `packages/ui/src/icons/index.ts` — placeholder export for the icon barrel
- Create: `packages/ui/src/icons/.eslintrc.cjs` (or equivalent flat-config override) — opt the icon directory out of the rule
- Create: `tests/eslint-no-inline-svg.test.mjs` — programmatic lint test verifying the rule fires outside the icon directory and is silent inside it
- Test: `pnpm lint` and the new test

### Acceptance Criteria

- [ ] Root config defines a rule that flags `<svg>` JSX in any file outside `packages/ui/src/icons/`
- [ ] The rule does NOT fire for files inside `packages/ui/src/icons/`
- [ ] `packages/ui/src/icons/index.ts` exists (may export nothing yet)
- [ ] Negative test (`<svg/>` outside the icons dir) reports the rule
- [ ] Positive test (`<svg/>` inside the icons dir) does not report the rule
- [ ] Existing app code is either clean or has its inline SVGs lifted to `packages/ui/src/icons/` in this PR

### TDD Steps

1. Write `tests/eslint-no-inline-svg.test.mjs`: lint a synthetic component with `<svg>`, assert violation; lint the same content placed in `packages/ui/src/icons/`, assert no violation. Run → FAIL.
2. Add the rule + icon-dir override in `eslint.config.mjs`. Create `packages/ui/src/icons/index.ts`.
3. Re-run negative + positive tests → PASS.
4. Run `pnpm lint`; if any existing component has an inline `<svg>`, extract it to a new icon component under `packages/ui/src/icons/` and import it.
5. Commit `chore(eslint): forbid inline SVG outside packages/ui/src/icons`; PR `Closes #<this-issue>`.
