### Goal

Enforce DDD architectural boundaries between `apps/*` and `packages/{domain,application,infrastructure,ui,testkit}` using `eslint-plugin-boundaries`, so cross-layer imports fail lint.

### Context

This is the third Phase 0 task and depends on B2 (ESLint flat config). The DDD layout is already in place at `packages/{domain,application,infrastructure,ui,testkit}` and `apps/web`. Without boundary enforcement, layers are guidelines only — this issue makes them mechanical rules.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> Architectural-boundary enforcement via `eslint-plugin-boundaries` matching the `packages/{domain,application,infrastructure,ui,testkit}` + `apps/web` layout

Per the Phase 0 issue table (row B3), the layer rules are:

- `domain` → no internal imports
- `application` → may import from `domain`
- `infrastructure` → may import from `application`, `domain`
- `ui` → may import from `domain`
- `testkit` → may import from `testkit`
- `apps/*` → may import from any package

Acceptance from the same row: a negative test fails when an import from `apps/web` is added inside `packages/domain`.

### Files

- Modify: `eslint.config.mjs` (root) — register `eslint-plugin-boundaries`, configure element types and rules
- Create: `tests/eslint-boundaries.test.mjs` — test that lints a synthetic offending file and asserts the violation
- Test: `pnpm lint` and the new test

### Acceptance Criteria

- [ ] `eslint-plugin-boundaries` is loaded by the root flat config
- [ ] `boundaries/elements` declares each of: `domain`, `application`, `infrastructure`, `ui`, `testkit`, `app` (or `apps`) with the correct `pattern`
- [ ] `boundaries/element-types` rule encodes the layer matrix above (deny-by-default; explicit allow lists per element)
- [ ] A negative test in `tests/eslint-boundaries.test.mjs` programmatically lints a temp file that imports from `apps/web` inside `packages/domain` and asserts ESLint reports a `boundaries/element-types` violation
- [ ] `pnpm lint` does not regress on the existing codebase (i.e. no lawful imports become illegal)

### TDD Steps

1. Author the negative test that lints synthetic source against the boundaries rule and asserts a violation. Run → FAIL (rule not configured).
2. Install `eslint-plugin-boundaries`; configure `settings.boundaries/elements` and the `boundaries/element-types` rule per the layer matrix.
3. Re-run negative test → PASS.
4. Run `pnpm lint` against the workspace; if any current code violates the new rule, decide per-case: real violation (fix), or rule too strict (refine matrix; document why).
5. Commit `chore(eslint): enforce DDD layer boundaries`; PR `Closes #<this-issue>`.
