### Goal

Replace the minimal Next.js ESLint config with a strict, type-aware flat config covering the workspace, loading the full plugin set listed in the canonical plan.

### Context

This is the second task in Phase 0 (Code Quality Foundation). All subsequent ESLint-based rule issues (B3 boundaries, B4 no-inline-SVG, B5 data-testid, B6 MDX/JSDoc) extend this foundation. Today `apps/web/eslint.config.mjs` only loads `next/core-web-vitals`. This issue introduces a root `eslint.config.mjs` plus a slimmed-down app-level config that extends it.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> ESLint flat config with type-aware rules: typescript-eslint strict + stylistic, react, react-hooks, jsx-a11y/strict, @next/next, import, unicorn, sonarjs, promise, deprecation, regexp, security, no-secrets, anti-trojan-source, jsdoc, perfectionist, no-only-tests, react-refresh, mdx

Acceptance from the Phase 0 issue table (row B2): `pnpm lint` runs and reports actual violations; the listed plugins are all loaded.

### Files

- Create: `eslint.config.mjs` (repo root) — flat config wiring all plugins below
- Modify: `apps/web/eslint.config.mjs` — extend root config; keep only Next-specific rules
- Modify: `package.json` (root) — add `lint` script (`eslint .` with reasonable ignores) and the new dev dependencies
- Test: `pnpm lint` from repo root

### Acceptance Criteria

- [ ] Root `eslint.config.mjs` exists and uses ESLint 9 flat-config form (`export default [...]`)
- [ ] Root config loads, at minimum:
  - **Core / language:** `typescript-eslint` strict-type-checked + stylistic-type-checked, `eslint-plugin-react`, `eslint-plugin-react-hooks`, `eslint-plugin-jsx-a11y` (strict), `@next/eslint-plugin-next`, `eslint-plugin-import`, `eslint-plugin-unicorn`, `eslint-plugin-sonarjs`, `eslint-plugin-promise`, `eslint-plugin-deprecation`, `eslint-plugin-regexp`, `eslint-plugin-jsdoc`, `eslint-plugin-perfectionist`, `eslint-plugin-react-refresh`, `eslint-plugin-mdx`
  - **Security:** `eslint-plugin-security`, `eslint-plugin-no-secrets`, `eslint-plugin-anti-trojan-source`
  - **Test quality (B11/B12 will exercise these):** `eslint-plugin-vitest`, `eslint-plugin-testing-library`, `eslint-plugin-jest-dom`, `eslint-plugin-playwright`, `eslint-plugin-no-only-tests`
  - **Hygiene + monorepo:** `@eslint-community/eslint-plugin-eslint-comments` (forbid orphan/unused disables, require reasons), `eslint-plugin-unused-imports`, `eslint-plugin-package-json` (lints every `package.json` in the workspace), `eslint-plugin-yml` (lints all `*.yml` / `*.yaml`, including `.github/workflows/`)
- [ ] `pnpm lint` runs end-to-end (it is acceptable — and expected — for actual violations to surface; this issue is about wiring, not a clean run)
- [ ] Type-aware rules use a `parserOptions.project` that points at the workspace's tsconfigs
- [ ] `apps/web/eslint.config.mjs` extends the root config rather than duplicating plugin loading
- [ ] No plugin from the list above is silently skipped (each must be referenced in the root config)

### TDD Steps

1. Add a smoke spec at `tests/eslint-config.test.mjs` (Node test runner or Vitest) that imports the root `eslint.config.mjs` and asserts the config array contains a flat-config entry with each required plugin name. Run → expect FAIL.
2. Install dev deps for every plugin in one `pnpm add -Dw` invocation.
3. Author root `eslint.config.mjs` wiring all plugins; rerun smoke test → PASS.
4. Run `pnpm lint`; if it crashes (config error vs rule violation), fix the crash. Rule violations surfaced are fine and not in scope here.
5. Commit `chore(eslint): add strict flat config with full plugin set`; open PR `Closes #<this-issue>`.
