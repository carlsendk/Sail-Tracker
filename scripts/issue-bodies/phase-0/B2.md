### Goal

Replace the minimal Next.js ESLint config with a strict, type-aware flat config covering the workspace, loading the full plugin set listed in the canonical plan.

### Context

This is the second task in Phase 0 (Code Quality Foundation). All subsequent ESLint-based rule issues (B3 boundaries, B4 no-inline-SVG, B5 data-testid, B6 MDX/JSDoc) extend this foundation. Today `apps/web/eslint.config.mjs` only loads `next/core-web-vitals`. This issue introduces a root `eslint.config.mjs` plus a slimmed-down app-level config that extends it.

### Rule curation

Plugins are loaded; rules from each plugin are enabled selectively per the curation below. Rules NOT enabled stay un-enabled (don't load-and-override-to-off; pick which presets/rules to apply).

**Do NOT enable:**
- `react/react-in-jsx-scope` — Next 15 has automatic JSX runtime; apply `react.configs['jsx-runtime']` so this rule stays off via curation rather than override.
- Prettier-overlap formatting rules: `react/jsx-indent`, `react/jsx-newline`, `react/jsx-one-expression-per-line` — these belong to B7 (Prettier + Stylelint), not B2.

**Enable + clean up violations in this issue (all 4 families chosen by operator):**
- JSDoc strictness: `jsdoc/require-jsdoc` + `jsdoc/require-file-overview` + `jsdoc/no-missing-syntax` + `sonarjs/file-header`
- Unicorn opinions: `unicorn/no-null` + `unicorn/prevent-abbreviations`
- Perfectionist sort family: `perfectionist/sort-imports` + `sort-objects` + `sort-modules` + `sort-union-types` + `sort-object-types`
- JSX style strictness: `react/jsx-no-literals` + `react/jsx-max-depth` + `sonarjs/arrow-function-convention`

**Also enable + clean up (default Phase 0 quality bar):**
- `security/detect-object-injection`, `security/detect-non-literal-fs-filename`
- `vitest/prefer-expect-assertions`, `vitest/require-hook`
- `sonarjs/declarations-in-global-scope`
- `package-json/require-description`
- `regexp/*` (sort-character-class-elements, require-unicode-sets-regexp, require-unicode-regexp)
- `@typescript-eslint/consistent-type-definitions`

### TDD Steps

1. Add a smoke spec at `tests/eslint-config.test.mjs` (Node test runner or Vitest) that imports the root `eslint.config.mjs` and asserts the config array contains a flat-config entry with each required plugin name. Run → expect FAIL.
2. Install dev deps for every plugin in one `pnpm add -Dw` invocation.
3. Author root `eslint.config.mjs` wiring all plugins per the "Rule curation" section above (skip the wrong-for-stack and B7-overlap rules; enable the curated set at `'error'`); rerun smoke test → PASS.
4. Run `pnpm lint`. Use `--fix` to clear auto-fixable violations. Then fix remaining violations rule-family by rule-family until `pnpm lint` exits 0 with 0 warnings + 0 errors. Commit per family for reviewability.
5. Final commit `chore(eslint): zero-warning baseline with curated strict ruleset`; do NOT push or open PR (controller does that after reviewers approve).
