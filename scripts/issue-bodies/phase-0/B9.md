### Goal

Wire husky + lint-staged for pre-commit autofix and commitlint for Conventional Commits enforcement, so bad commits never land.

### Context

This is the ninth Phase 0 task. It depends on B2 (lint-staged runs ESLint) and B7 (lint-staged runs Prettier). The repo already has an `install-git-hooks.mjs` helper; this issue replaces or complements that with the husky/lint-staged stack and adds commitlint for message validation.

**Why commitlint matters beyond style:** the repo already runs Release Please (`.github/workflows/release-please.yml` + `.release-please-config.json`) which parses Conventional Commits to auto-generate `CHANGELOG.md` and bump `release-please-manifest.json`. Without commitlint, contributors can land non-conventional messages that Release Please silently ignores, drifting the changelog. commitlint is the upstream gate for that whole pipeline.

### Files

- Create: `.husky/pre-commit` — invokes `pnpm exec lint-staged`
- Create: `.husky/commit-msg` — invokes `pnpm exec commitlint --edit "$1"`
- Create: `.lintstagedrc.json` — patterns + commands per file type
- Create: `commitlint.config.mjs` — extend `@commitlint/config-conventional`
- Modify: `package.json` (root) — `prepare` script runs husky install; add dev deps for `husky`, `lint-staged`, `@commitlint/cli`, `@commitlint/config-conventional`
- Modify (or remove): `scripts/install-git-hooks.mjs` — superseded by husky; keep only if it does something husky does not
- Test: dry-run a commit with a bad message + a dirty staged file

### Acceptance Criteria

- [ ] `pnpm install` runs `husky install` via the `prepare` script
- [ ] `.husky/pre-commit` exists, is executable, and invokes lint-staged
- [ ] `.husky/commit-msg` exists, is executable, and invokes commitlint
- [ ] `.lintstagedrc.json` configures: `*.{ts,tsx,js,mjs}` → `eslint --fix` then `prettier --write`; `*.{md,mdx,json,yaml,yml}` → `prettier --write` then `cspell --no-must-find-files --quiet`; `*.css` → `stylelint --fix` then `prettier --write`
- [ ] A test commit with message `bad commit` is rejected by commit-msg hook
- [ ] A test commit with a TS file that has lint violations triggers lint-staged auto-fix; if violations remain post-fix, the commit is blocked
- [ ] Existing `scripts/install-git-hooks.mjs` is either removed or has its responsibilities moved to husky

### TDD Steps

1. Install dev deps; add `prepare` script. Run `pnpm install` to bootstrap husky.
2. Author the two husky hooks + lint-staged + commitlint configs.
3. Manual test (record output in PR body): `git commit --allow-empty -m "bad commit"` → expect rejected; `git commit --allow-empty -m "feat: hello"` → expect pass.
4. Manual test: stage a TS file with a lint violation, attempt commit, observe lint-staged behavior, document in PR body.
5. Decide on `scripts/install-git-hooks.mjs` (remove or rewrite to delegate to husky).
6. Commit `chore(git): wire husky, lint-staged, commitlint`; PR `Closes #<this-issue>`.
