### Goal

Lint MDX docs and require JSDoc on exported APIs in the `domain`, `application`, and `ui` packages.

### Context

This is the sixth Phase 0 task and depends on B2. Our docs are MDX-rendered Nextra; without lint, they drift in style. JSDoc on the public surface of `domain`/`application`/`ui` ("ES-docs") gives editor hovers and feeds future doc-generation.

### Embedded Spec

From `docs/plans/plan.md` § Phase 0 → Scope:

> ESLint flat config with type-aware rules: typescript-eslint strict + stylistic, react, react-hooks, jsx-a11y/strict, @next/next, import, unicorn, sonarjs, promise, deprecation, regexp, security, no-secrets, anti-trojan-source, jsdoc, perfectionist, no-only-tests, react-refresh, mdx

Per the Phase 0 issue table (row B6): one MDX file lints; one missing-JSDoc on an exported function fails. Coverage: MDX docs linted; JSDoc required on exported APIs in `packages/{domain,application,ui}`.

### Files

- Modify: `eslint.config.mjs` (root) — wire `eslint-plugin-mdx` against `**/*.mdx` and `eslint-plugin-jsdoc` with `require-jsdoc` (or `jsdoc/require-jsdoc`) scoped to `packages/{domain,application,ui}/src/**` and only for exported functions/classes
- Create: `tests/eslint-mdx.test.mjs` — programmatic lint test that lints a tiny MDX snippet and asserts plugin engagement
- Create: `tests/eslint-jsdoc.test.mjs` — programmatic lint test that lints an exported function without JSDoc and asserts a violation
- Test: `pnpm lint`, both new tests

### Acceptance Criteria

- [ ] `eslint-plugin-mdx` is registered against `**/*.mdx`
- [ ] At least one of `docs/**/*.md(x)` files lints cleanly through the MDX plugin (or has known violations recorded)
- [ ] `eslint-plugin-jsdoc` is registered with `jsdoc/require-jsdoc` enabled for exported `FunctionDeclaration`, `MethodDefinition`, `ArrowFunctionExpression` (when assigned to an exported `const`), and `ClassDeclaration` in `packages/{domain,application,ui}/src/**`
- [ ] An exported function without a JSDoc block in those packages fails lint
- [ ] An exported function WITH a JSDoc block does not fail lint
- [ ] Internal/private symbols inside the same packages are not required to have JSDoc

### TDD Steps

1. Write `tests/eslint-jsdoc.test.mjs` linting `export function foo() {}` (FAIL) and `/** … */ export function foo() {}` (PASS) within a synthetic file path under `packages/domain/src/`. Run → FAIL.
2. Write `tests/eslint-mdx.test.mjs` linting a `### header\n\ncontent` snippet as MDX. Run → FAIL.
3. Install `eslint-plugin-jsdoc` and `eslint-plugin-mdx`; wire both in the root config with the scoping above.
4. Re-run both tests → PASS.
5. Run `pnpm lint`. If existing exported APIs in those packages lack JSDoc, add minimal one-line JSDoc or carve out `/* eslint-disable */` only as a deliberate, justified follow-up note in the PR description.
6. Commit `chore(eslint): add MDX + JSDoc rules`; PR `Closes #<this-issue>`.
